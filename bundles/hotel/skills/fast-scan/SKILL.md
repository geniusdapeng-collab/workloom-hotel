# 快速体检（快照快扫）

## 〇、定位

「先体检，再托管」客户旅程的**第一公里**：业主坐在现场，授权 PMS/OTA 后 15–30 分钟拿到《酒店快速体检报告》——"原来我的店每年在漏这些钱"。这是购买决策的催化剂，也是质检模式（audit_only）的旗舰技能。

与持续体检的分工：
- **本技能（快照快扫）**：基于历史数据快照的存量问题，15–30 分钟一遍过——多 OTA 倒挂/低于保底价/促销失误/超售漏售痕迹/佣金错算/存量未回差评/担保异常/断点高频项。
- **持续体检（inspection-suite，1–2 周）**：需要时间才能观察的问题——差评响应时长实测、SLA 履约率、夜班断点行为、趋势与峰值（节假日/展会）表现。

## 一、何时调用

- 售前演示：业主现场授权 1–N 家门店后立即触发（目标：当场出报告）。
- 新客户接入质检模式时自动执行一次（基线快照），此后转入持续巡检。
- 客户手动触发"重新体检"（如旺季/展会后、整改后复查对比）。

## 二、输入契约

- 连接器只读快照（PMS/OTA 只读 scope 授权）：
  - 订单流水（近 90 天，含取消/no-show/退款/担保标记）
  - 房态与房价（房型主数据/价格日历/各渠道在售状态/问题房记录）
  - 评价数据（各 OTA 存量未回复差评/评分分布/关键词）
  - 渠道账单（最近 1–2 个结算周期的 OTA 佣金账单）与渠道绩效指标
- 门店档案（保底价/价格带/房型基准参数，缺失时用同商圈同档位默认值并在报告中标注"按商圈基准估算"）。
- 时间预算参数：默认 30 分钟硬上限（超时出部分报告并标注覆盖度）。

## 三、执行步骤（五线静态分析，一遍过）

1. **快照拉取与口径校准**（≤5 分钟）：动作=PMS 与各 OTA 连接器只读拉取，归一化为统一数据模型（房型/渠道字段映射）；产出物=快照数据集+覆盖度清单；回执=各源拉取回执（行数/时间窗/完整率）。
2. **价格健康线**：动作=同房型同日跨 OTA 价差扫描（倒挂 >10% 告警，对齐 R17 口径）→ 售价 vs 保底价（一店一档 business.floor_price 同源）破防清单 → 促销价异常（低于近 30 天最低价/活动价叠加失误/节假日漏调价）；产出物=价格问题清单（含每间夜损失估算）；回执=计算过程快照。
3. **房态库存健康线**：动作=各渠道可售数 vs PMS 实盘逐日核对（超售：可售为负/漏售：有房未上架）→ 库存同步失败记录盘点 → 问题房（维修中/锁房）占比与时长；产出物=超售漏售双清单+问题房清单（含预期房晚损失）；回执=计算过程快照。
4. **渠道健康线**：动作=最近结算周期 OTA 账单与 PMS 订单逐笔勾稽 → 差异分类（佣金错算/费率用错档/退款未冲抵/no-show 担保未结算）→ 渠道贡献与佣金率异常排名；产出物=渠道渗漏清单（含估算追回金额）；回执=勾稽差异明细。
5. **口碑健康线**：动作=存量未回复差评（>24h 清单，对齐 R19 SLA）→ 评分分布异常渠道/房型 → 差评关键词聚类（卫生/隔音/前台/早餐）→ 好评资产盘点（可引用卖点）；产出物=口碑风险清单+差评处置建议草稿；回执=扫描回执。
6. **安全与合规线**：动作=担保订单异常盘点（R5 同源：担保未扣/异常取消高频）→ 断点高频项统计（对接失败/同步失败/设备告警历史）→ 安全事件记录核查（只读，R10 禁区不触碰）；产出物=安全合规预警单；回执=扫描回执。
7. **汇总成报告**：动作=五线结果按 P0/P1/P2 分级 → 每条附"问题+证据+建议动作+估算年化挽回金额" → 汇总一店一份《酒店快速体检报告》+ 多店总览（**按年化挽回金额排序的 Top10 行动清单**）；产出物=报告卡片（IM 触达+工作台可查）；回执=报告事件 ID 与触达回执。

## 四、边界与围栏

- **全程只读**：audit-only patch 生效——一切 PMS/OTA/IoT 写操作物理 block；本技能只向系统事件库写入发现与报告。
- **估算口径透明**：所有"挽回金额"逐条标注计算口径与置信度（精确值/按商圈基准估算/经验估计），禁止把估算说成确定值。
- **时间纪律**：30 分钟硬上限；某数据源超时→该线标注"未覆盖"并降级出部分报告，不阻塞整体。
- 不做什么：不做趋势预测（需观察期数据）、不做差评响应时长实测（需在线观察）、不做任何处置动作（只出建议）。

## 五、与其他技能的协作

- 产出 → `inspection-suite`（持续巡检接管，验证快扫发现并监测时变问题）
- 产出 → `morning-briefing`（体检发现并入晨报"风险"栏直至闭环）
- 价格发现 → `overbooking-parity-guard`（托管后接管倒挂/超售实时防护）；渠道渗漏 → `channel-reconciler`（托管后逐笔对账常态化）；口碑发现 → `review-crisis` / `review-asset-mining`（托管后处置与资产化）
- 报告中的整改项被客户确认后 → 对应域技能生成执行草案（影子模式起）
- 复购/复查场景：与上次报告 diff，产出《整改闭环率》对比卡

## 六、验收用例

- 接入含已知倒挂房型的演示门店，30 分钟内产出报告且该房型出现在价格健康清单（含渠道/价差/建议价）。
- 报告中每条估算金额均带口径标注；任一数据源缺失时报告正常产出且对应线标注"未覆盖"。
- 全程事件库无任何 PMS/OTA 写操作记录（RuleImpact 全为只读动作）。
