# 审批机制复盘与水位调整（2026-09-23 · v1）

> 结论：现行机制"红线强、水位偏高"。8 条 block 红线精准且必须全部保留；
> 真正的过量介入来自两处结构性缺口——`default_level: review` 兜底过宽（未命中规则的写操作一律人审），
> 以及日常高频低风险动作缺少 auto 白名单。本次不降低任何红线，只为低风险动作补 auto 通道（R21–R24）。

## 1. 现状盘点（以 hotel-baseline/v3 + 决策三级分流为准）

| 层 | 机制 | 数量 | 评价 |
|---|---|---|---|
| block（熔断） | R2 保底价 / R5 担保异常 / R9 触达合规 / R10 安全禁区 / R16 夜班高危 / R17 倒挂 / R18 超售 | 8 | **精准，全是钱、安全、合规——全部保留，一条不动** |
| review（人审） | R3/R4/R6/R8/R11–R15/R19/R20 + **default_level: review** | 11 + 兜底 | 规则内 11 条基本合理；**兜底 review 是过量介入的主因** |
| auto（自动） | R1 调价≤8% / R7 夜班微调≤3% | 2 | 覆盖面太窄：送物、报修、排房、好评回复、入退调度等日常高频动作全部没有 auto 通道 |
| 决策分流 | micro/standard/major 三级（金额 2 倍上限 / 不可逆 / 多域 → major 上浮老板） | — | 合理；金额无 cap 声明 → major 是 fail-closed，但要求 Bundle 为常用金额动作补齐 capKey |

## 2. 介入量测算（以演示工作区 30 天数据为参照）

- 已自主完成 116 项作业 vs 待拍板 3 项——表面比例健康；
- 但演示数据是种子直写，**生产路径下**这些动作（工单办结、好评回复、排房、入退调度、内部晨报）全部会命中 `default_level: review`——意味着一家 20–50 间房的酒店，老板每天醒来要批 30+ 件"送两瓶矿泉水"级别的事项，**审批疲劳 → 要么全部秒批（审批形同虚设），要么弃用**。

## 3. 水位调整原则

1. **钱、安全、合规、对外发布**：维持人审/熔断，绝不放宽（R2/R9/R10/R16/R17/R18 + R3/R4/R13/R14/R15）。
2. **可逆、单域、无费、内部**：给 auto 通道，但**必须留回执并在晨报中可回看**（无回执不算完成的不变量不变）。
3. **差评/赔偿/涉费承诺**：维持人审——这是小酒店最伤口碑的三类事。
4. 老板的可信度是挣来的：新 auto 通道默认开启后，由命中率回测（captain scorecard）持续观察，连续异常自动收紧一档（既有机制，无需新代码）。

## 4. 本次落地（R21–R24，全部 auto，均要求回执留痕）

| 规则 | 覆盖动作 | 理由 |
|---|---|---|
| R21 好评与中性评价回复 | review.reply（rating ≥ 4） | 好评回复无资金与口碑风险；差评仍走 R6 必审（deny 优先不受本条影响） |
| R22 常规服务工单办结 | service.ticket.complete（不涉费、不涉赔偿） | 送物/报修是最高频动作；涉费涉赔仍受 R13/R14 约束 |
| R23 智能排房与入退调度 | booking.confirm / service.ticket.advance（无投诉标记） | 可逆、单域、有 SOP；超售仍受 R18 熔断 |
| R24 内部经营内容生成 | content.internal / funnel.weekly / night.package.deliver / ceo.briefing | 纯内部汇报，不对外发布；对外发布仍受 R3/R15 必审 |

## 5. 后续建议（未本次实施，供评审）

- **A. 三套审批模板差异化**：民宿一人店（无第二审批人）建议 default_level 降为 auto-with-receipt 并强化晨报告知；集团门店维持 review。模板差异应进 approval_matrix 而非改基线。
- **B. L4 上浮误报治理**：为 bundle 内常用金额动作（退款、采购、赔偿）在 presets 补齐 amountCtx.capKey 声明，减少"金额动作缺少自治上限 → 一律上浮老板"的误报。
- **C. 审批批处理**：同类低风险 review（如多条好评回复）支持晨报合并呈批，一次手势批量采纳（P3 已有批量通道，建议默认启用）。
